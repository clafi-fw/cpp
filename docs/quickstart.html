Quick Start

Build a first ClaFi application from four selections

All manuals

ClaFi is a C++20 UI framework stored in a git repository. An application can be in any folder on disk and builds against a clone of that repository. The clone also contains the applications included with the framework. The form below generates the source files, build files and run command.

An application has two parts. A module named after the application contains the code shared by Windows and Linux: the window, the form and its controls. The entry point of each platform constructs the platform and the application. To build for the other platform, use its entry point.

Before you start

Clone github.com/clafi-fw/cpp and install the toolchain for the target platform. The application folder can be anywhere; the build files contain the path to the clone.

PlatformWhat the build needs
Windows 10 or 11 Visual Studio 2026 with the Desktop development with C++ workload. This installs MSVC, the Windows SDK and the module scanner. The project uses the default toolset: v145 in Visual Studio 2026, v143 in 2022.
Linux A Wayland session on x86-64 with AVX2 and FMA. The build requires clang 22 with libc++ module support, CMake 4.3 or newer, Ninja 1.11 or newer, and the development packages below. Fedora 43 with KDE is the verified configuration.
The Linux packages

Fedora:

sudo dnf install clang libcxx-devel libcxxabi-devel cmake ninja-build pkg-config git \
    wayland-devel wayland-protocols-devel wlr-protocols-devel \
    libxkbcommon-devel freetype-devel harfbuzz-devel fontconfig-devel \
    libunibreak-devel libpng-devel dbus-devel

Debian and Ubuntu:

sudo apt install clang libc++-dev libc++abi-dev cmake ninja-build pkg-config git \
    libwayland-dev libxkbcommon-dev libfontconfig-dev libfreetype-dev \
    libharfbuzz-dev libpng-dev libdbus-1-dev libunibreak-dev

wayland-protocols 1.48 or newer is required, and wlr-protocols must provide a pkg-config file. A distribution with older versions requires building both from source. CMake 4.3 and clang 22 are newer than most distributions provide; a distribution's clang package is often older, and clang 22 with libc++ is available from the LLVM repository or the release image. The release image contains the exact versions used for releases and can serve as a reference.

A console program has no form. It reads its arguments, writes to the standard output and returns an exit code. Its module is the same on both platforms.

What the framework provides

The framework provides the following in a windowed application:

The application menu. The button at the left of the title bar opens it. It contains the Settings page, the Information page and the theme picker on the Settings page. Commands can be added with connectAppCommand.

The settings file. It is stored in the user's application data folder under the publisher and application names. It contains the window placement, the selected theme and the menu settings. Before creating the folder, the Settings page asks the user for permission.

Themes. The application declares its default theme. The Settings page lists the available themes and stores the selection. The generated windowed application uses the starter theme from the showcase source. See Application Themes.

The window frame. The framework draws the title bar, the sizing buttons and the frame, and applies display scaling. On desktops that support it, the window placement is restored when the application starts.

Custom settings. An application adds groups of its own to the Settings page with connectAppSettings. The generated example keeps one check box in the application's config, under a section named after the application.

Adding a control

In a windowed application, each control is a reference member of MainForm and is created in its declaration. The constructor connects the handlers:

// In the class, beside the other controls:
Button& m_reloadButton{ body().add<Button>(L"Reload") };

// In the constructor's body:
m_reloadButton.onClick([](ClickEvent& event) {
    MessageDialog dialog{
        *event.control,
        L"Reload",
        Text{ L"Nothing to reload yet." }
    };
    dialog.add(DialogAnswer::Ok);
    dialog.execute();
});

add<Control> returns a reference to the new control. Its arguments set properties such as Padding, Spacing, MinSize and Text. Use body() for a single-window application and m_homeBody for a page.

The two builds

The framework has two builds, one for each platform.

Visual StudioCMake, Ninja and clang
Platform Windows 10 and 11: Win32, Direct2D and the CPU rasterizer Linux: Wayland and the CPU rasterizer
Compiler MSVC at /std:c++20, with module scanning on clang 22 with libc++, and import std
Build definition A Visual Studio project that references ClaFi.vcxitems as a shared items project A CMakeLists.txt in the application folder that adds the clone as a subdirectory
Requirements x64. Add new files to the project; otherwise they are not compiled. Ninja; -stdlib=libc++; an explicit build type; a new build directory after changing an import.

If the build stops

  • Visual Studio reports errors in the framework sources. IntelliSense does not process C++20 modules; use ReSharper C++ or clangd for navigation and read the compiler output. See the FAQ.
  • clang reports a name that the source does not import. A stale module file can still provide it. Delete the build directory and configure again.
  • A new file is not compiled. Add it to the Visual Studio project, or to add_executable or target_sources in CMake.
  • The build cannot find the clone. Check the shared-items reference in Visual Studio, or CLAFI_ROOT in CMake.
  • The build is for another architecture. The framework supports x64 on Windows and x86-64 with AVX2 and FMA on Linux; 32-bit and ARM are not supported.
