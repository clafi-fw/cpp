Documents

A document browser opens and edits one kind of file across a set of filesystem folders.

Document storages

Home shows storage folders as tiles. Add storage opens a popup with editable Name and Location fields, a Browse button, and a Read-only checkbox. Name defaults to the folder name. Select a storage tile and press Properties to edit it. The popup opens under the button.

Delete asks whether to remove the storage from the application or also delete the folder and its contents from disk. The first option leaves the files on disk. Disk deletion is available for writable folders that contain no other registered storage.

When application settings are enabled, the browser keeps storage names, locations, and access settings there. Each storage has its own path segment in the browser, so files with the same name open independently. Changing a storage's folder gives the replacement a new path segment. An open tab keeps the file it was opened on and can save a copy after its original storage is detached.

A read-only storage supports opening documents. The browser blocks New, Rename, and Delete in that storage. Save falls back to Save As for read-only documents. In Save As, the destination picker shows each writable storage's name and location. The current storage is selected when it is writable, and a sole writable storage is selected automatically. OK becomes available once a storage is selected.

Building a document browser

Import ClaFi.Documents. Derive a DocumentsFolder to define the file format, icons, and what counts as an edited file. Keep it alive while the browser runs. Pass it to DocumentsApplication::run as the primary folder and format for all the browser's storages. The application constructor adds storage settings to the root schema.

Override DocumentsFolder::defaultStorages() to supply additional folders at startup. Each StorageDefault has an absolute location, an optional display name, and a read-only flag. A read-only default locks that folder's access in Properties. The browser remembers when a user disconnects a default. If an application stops offering a default, its tile disappears and its saved tabs keep their original storage ID.

DocumentsBrowser takes the application's home-page and document-page types. Pages receive the format folder through folder() and the folder they show through storageFolder(). Custom lists can read the DocumentStorageView construction property for the folder and for the flag that identifies the main home view. On home, StorageTilesView supplies the current storage entries. Custom lists can render them with addStorageTile and implement IDocumentTiles::rebuild to refresh them after a change. A custom browser can use documentPath to get a browser path from a storage and a filename.

Working with files

Use DocumentsFolder::saveDocument, createFile, renameFile, and deleteFile for browser commands. These functions enforce a storage's access setting. canWriteFile also checks the file's location and rejects symbolic links. The virtual writeDocument is the application's format implementation.

readTextFile reads UTF-8 with or without a byte order mark and folds CRLF line endings to LF. On Windows, pass TextFileFallback::WindowsAnsi to use the active ANSI code page when an unmarked file contains invalid UTF-8. For files known to use code page 1251, pass TextFileFallback::Windows1251 on either platform. writeTextFile writes UTF-8 with CRLF line endings. Pass Utf8Bom::Write to include the UTF-8 signature required by some readers.
