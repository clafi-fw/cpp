Documents

Building a document browser

A document browser uses one file format across a set of filesystem folders. Import ClaFi.Documents and derive a DocumentsFolder to define the format, icons, and what counts as an edited file. Keep the folder alive while the browser runs. Pass it to DocumentsApplication::run as the primary folder and format for all the browser's storages. The application constructor adds storage settings to the root schema.

DocumentsBrowser takes the application's home-page and document-page types. Pages receive the format folder through folder() and the folder they show through storageFolder(). Custom lists can read the DocumentStorageView construction property for the folder and for the flag that identifies the main home view. On home, StorageTilesView supplies the current storage entries. Custom lists can render them with addStorageTile and implement IDocumentTiles::rebuild to refresh them after a change.

Document storages

Override DocumentsFolder::defaultStorages() to supply additional folders at startup. Each StorageDefault has an absolute location, an optional display name, and a readOnly flag. The folder name supplies the display name when none is specified. Setting readOnly enforces read-only access even if application settings request write access. The browser remembers disconnected defaults across runs.

Disconnecting a storage leaves its files on disk. Read-only and disconnected storages are excluded from DocumentsBrowserBase::writableStorages(), which supplies the destinations for saving a copy. The browser also prevents deleting a storage directory that contains another registered, available storage.

Storage IDs and document addresses

The first segment of a document's browser address identifies its storage. The primary folder uses Storage1, and each added folder takes the first free numbered ID. If the Reports folder has ID Storage2, browser.documentPath(reports, L"Report.gsps") returns /Storage2/Report.gsps for navigation. Use reports.fileOf(L"Report.gsps") to obtain the filesystem path for I/O.

With application settings enabled, the Reports entry in DocumentStorages stores Id=Storage2 alongside its filesystem Location. In OpenTabs, a tab displaying the file has its own ID, for example Id=Tab1, and a Path=/Storage2/Report.gsps. To restore the tab, the browser resolves Storage2 to the registered folder and looks up Report.gsps there. Back and Forward history keep the same address in each visit's Url field.

Changing a storage's display name preserves its ID. Replacing its location assigns a new ID. A tab or history entry that refers to the disconnected storage reserves the old ID, so its address continues to identify the original storage.

Working with files

Populate DocumentsFolder::templates() with a DocumentTemplate for each kind of starting document the application supplies. The browser uses a sole template directly and offers a choice when several are registered. To create a file programmatically, call storage.createFile(&documentTemplate) for that template or storage.createFile() for an empty file. Both calls return the new filename on success and an empty string on failure.

Use DocumentsFolder::saveDocument, createFile, renameFile, and deleteFile for browser commands. These functions enforce a storage's access setting. canWriteFile also checks the file's location and rejects symbolic links. The virtual writeDocument is the application's format implementation.

readTextFile reads UTF-8 with or without a byte order mark and folds CRLF line endings to LF. On Windows, pass TextFileFallback::WindowsAnsi to use the active ANSI code page when an unmarked file contains invalid UTF-8. For files known to use code page 1251, pass TextFileFallback::Windows1251 on either platform. writeTextFile writes UTF-8 with CRLF line endings. Pass Utf8Bom::Write to include the UTF-8 signature required by some readers.
