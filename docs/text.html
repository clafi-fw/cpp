Writing ClaFi Text

Words in runs, each in a style of a sheet

All manuals

Introduction

A Text is its words in runs. A run is a stretch of characters in one style, with the link it goes to and the anchor it is, where it has them. The runs follow one another with no gap, so every character has exactly one style.

Every style is held in a sheet. A text is built over a sheet - the application's, where none is given - and finds a style there by its name. The sheet says what a name looks like: a family, a size, a weight, a slant, an ink. The theme says what an ink is when the text is drawn, so a text keeps its meaning through a theme change.

A Text is cheap to build and safe to keep. Building one every paint is the normal way to use it: the shaping is cached behind the engine, and a rebuilt Text that says the same thing hits that cache.

This manual is about what a text says: its runs, styles, colours, paragraphs and links. How a control holds its text, draws it and answers for it is the Working with Text in Controls manual.

Module imports: ClaFi.Core.TextEngine.Text for Text, the wrappers and TextFormat, ClaFi.Core.TextEngine.StyleSheet for StyleSheet, and ClaFi.Core.TextEngine.Types for TextStyle, TextStyles, the paragraph tags and the inline objects. Ink, InkGrade, InkColor and Color are declared in ClaFi.Core.System.UiTypes, and ClaFi.Core.System.InkWell names the inks - see the Colour manual.

Quick Start

A text is written as words and wrappers. A wrapper lays a style, an ink, a link or an anchor over the words it holds, and ends where its braces do:

Text text;
text << StyledText{ TextStyles::Section, L"Performance" } << k_endLine
     << ColoredText{ InkGrade::Muted, L"Frames: " }
     << ColoredText{ InkColor::Accent, frameCount };

// The same, as one expression.
Text same{
    StyledText{ TextStyles::Section, L"Performance" }, k_endLine,
    ColoredText{ InkGrade::Muted, L"Frames: " },
    ColoredText{ InkColor::Accent, frameCount }
};

Building Text

The stream

Everything is written with operator<<. The variadic constructor is the same sequence written as one expression, which is what makes a Text usable as a control property. A sheet given first is the sheet the text is built over - see Style sheets.

operator= takes any one of the same arguments and states the whole text rather than adding to it. Assigning one Text to another copies or moves it, its sheet with it, so a text is an ordinary value to hold in a member or hand back from a function.

Text caption;
caption << L"Opening ";                       // adds
caption = L"Ready";                           // replaces
caption = other.selectedText(range);          // moves
caption = Text{ ColoredText{ InkColor::Accent, name }, L" saved" };   // several parts

An assignment operator takes exactly one argument, so a text built from several parts is spelt as a Text and moved in, as the last line shows.

The constructor stays explicit. It accepts any argument list at all, so an implicit one would offer a Text conversion from every type in every overload set it appears in. Name the type where a Text is built - Text{ L"Ready" } - and assign without it.

WrittenEffect
std::wstring_view, std::wstring, const wchar_t*, wchar_t, int, std::size_tAppends words. A count - a line, a column, a length - is written as the std::size_t it is held in.
k_endLineEnds the paragraph. It is the character L'\n', written as any other wchar_t.
StyledText, ColoredText, BoldText …Words with a style, an ink, a link or an anchor laid over them - see Wrappers.
TextAlign, TextIndent{ f }, TextLineSpacing{ f }The look of the paragraph being written and of those after it - see Paragraphs.
Space{ w }, FlexSpace{}, TabTo{ x }, VSpace{ h }Inline spacing objects - see Spacing and Icons.
InTextIcon{ ... }A drawn object that sits in the text flow.
const Text&Appends another text, its runs and its paragraph looks.

A number with a format goes through std::format: ColoredText{ InkGrade::Muted, std::format(L"{:.1f} ms", elapsed) }.

The rest of the surface is small: plainText(), styles(), empty(), clear(), hash(), hasFlexSpace(), forEachRun(visit), paragraphLookAt(start), anchorRange(name), linkAtCaret(pos), firstLink(), and the editing calls replaceText, selectedText, restorableText and restoreText - see Copying and Moving Text.

Two texts are equal when their words draw alike: over one sheet, with the same named styles, the same characters in the same fields and script levels, and the same links, anchors, objects and paragraph looks - whichever wrappers stated those, and in whatever order the texts were written.

Wrappers

WrapperLays over its words
StyledText{ name, ... }The style of that name, found in the text's sheet - see Styles.
ColoredText{ ink, ... }An ink: an Ink, an InkGrade, an InkColor, or a Color stated outright - see Colour.
BoldText{ ... }, ItalicText{ ... }Weight and slant.
SizedText{ size, ... }A size in design pixels.
FamilyText{ family, ... }A font family by name.
SuperscriptText{ ... }, SubscriptText{ ... }A run off the baseline, at a smaller size.
LinkText{ target, ... }A link - see Links and Anchors.
AnchorText{ name, ... }An anchor a link reaches.

What a wrapper holds is written first, and the wrapper is laid over it - words, numbers, objects, other wrappers, and a Text built over several statements:

Text names;
for (const Entry& entry : entries)
    names << entry.name << k_endLine;
caption << ColoredText{ InkGrade::Muted, names };

The inner wins. A wrapper fills only the fields its words leave unstated, by themselves or through their style. So the family in FamilyText{ L"Georgia", StyledText{ TextStyles::Section, title } } is Section's own: the face goes inside the style, or into a style of the application's own based on Section - see Style sheets. Of two named styles, one inside the other, the inner is the run's style, and what the outer states beyond it is copied in as the run's own fields.

A wrapper that holds no character writes nothing.

A named value is held by reference and a temporary by value, so a wrapper kept in a variable must not outlive the named values it was given. Written straight into a text, as above, it never does.

Scripts compound. A script takes the size of what it stands on down by a fixed factor and steps the baseline by a share of that size, so L"2", SuperscriptText{ L"2", SuperscriptText{ L"n" } } comes out as a tower of three sizes. The line keeps its height for a script: a raised run stays inside the ascent of the run it stands on, and a lowered one whose letters descend can reach below what its line was measured at.

Styles

The framework's styles

TextStyles holds the names of the framework's styles. The framework's sheet holds the styles themselves, and every sheet reaches them where it does not restate one:

NameDrawn as
TextStyles::Titlesans-serif 24, bold
SubTitlesans-serif 17
Headingsans-serif 16, semibold
SubHeadingsans-serif 14
Sectionsans-serif 12, bold
SubSectionsans-serif 12, italic
Bodysans-serif 12 - the face, size, weight and slant a run and its format leave unstated
SubBodysans-serif 10
Codemonospace 12

The two families are generic - GenericFamily::SansSerif and GenericFamily::Monospace - and each platform resolves them to a face of its own: DirectWrite is handed Segoe UI and Consolas for them, and fontconfig reads both names as the aliases its configuration defines. A concrete family is passed through as written and stands or falls on the fonts installed.

Style sheets

A StyleSheet holds named styles over a parent sheet. find answers the sheet's own style of a name, else its parent's, up to the framework's sheet, which is over none. A TextStyle states the fields it sets and takes the rest from the style it is based on:

StyleSheet projectStyles{ &StyleSheet::application() };
projectStyles.set(TextStyle{
    .name = L"Note",
    .base = projectStyles.find(TextStyles::SubBody),
    .ink = InkWell::spotInk(),
});
Text caption{ projectStyles, StyledText{ L"Note", L"Read this first" } };

A style states a family, a size, a weight, a slant, an ink and script levels, each where it sets one. A size or a family a whole application uses is a style of its own, named where it is used.

The application's sheet is the one AppParams::styleSheet states, or the framework's where it states none. A text built with no sheet given is over it, so an application states its styles once and names them everywhere:

const StyleSheet& appStyles()
{
    static const StyleSheet sheet = []() {
        StyleSheet built;
        built.set(TextStyle{
            .name = L"Readout",
            .base = built.find(TextStyles::Body),
            .fontSize = 11.0f,
        });
        return built;
    }();
    return sheet;
}

params.styleSheet = &appStyles();
// ... and anywhere in the application:
Text{ StyledText{ L"Readout", value } };
CallDoes
set(style)States a style under its name and answers the sheet's own. A name the sheet holds keeps its address and takes the new fields and base.
find(name), findOwn(name)The style of that name, up the parents or the sheet's own; none where none has it.
rename(name, newName), remove(name), moveTo(name, position)Edits the list.
takeStyles(other)States the other's named styles over the sheet's own, each named alike keeping its address, and removes the sheet's own the other lacks.
styles()The named styles the sheet lists, in its order.
StyleSheet::framework(), StyleSheet::application()The framework's sheet, and the application's.

The sheet outlives every text over it and every text based on one of its styles. Each style stays at one address for the sheet's life. A sheet is never assigned - takeStyles states another's styles over its own - and a temporary sheet given to a Text is refused at compile time.

A text over the sheet can outlive the controls that showed it: the text engine keeps a copy of every text it lays out, and a tooltip fading out paints the words it was given. A sheet that would go while the program runs is kept until the windows that drew its texts are gone.

A control given its text as a Text takes it whole while its own text holds nothing, the sheet it was built over with it, so the words are set in that sheet's styles. A second Text, a view or a literal is written after what the control holds, in the control text's sheet. An expander's setHeaderText and an in-place editor take their text whole the same way.

A name the sheet holds is the sheet's style. A style named as one up the parents stands in for it: everything found through the sheet takes it, and so does every base in the sheet. A sheet's own Code in the spot ink is Code in that ink for every style based on Code.

An edit redraws. A change to a style a sheet holds, a rename and a removal move StyleSheet::revision() on and raise StylesEditedEvent, and every window lays out again. A style added under a name nothing holds is no edit, since no text is set in it yet.

A removed style leaves the list and stays where it stands, so a text based on it draws as it did. The styles based on it are based on its base instead.

A name found nowhere sets the words in no style and raises UnknownStyleEvent, which the application logs once per name.

A text's own styles

A text keeps its runs' styles in a sheet of its own, over the sheet it is built over - see styles(). Each run is set in a style named none, stating the fields the run sets over a base the text reaches. The text holds each look once, so two runs drawn alike share a style.

A style from elsewhere goes by its name. Where a text is put in another, pasted or selected, each run's base is found in the receiving text by its name, its own styles first:

  • a name the receiving text reaches is that style, which draws the words
  • a name it reaches none of comes as a named style of the text's own, a copy of the style based on its base as found the same way

So a range copied out of a document set in its own styles pastes into another document in that document's styles of the same names, and in the copied ones where it has none.

Colour

ColoredText names an ink - an InkColor at an InkGrade - and states no tone of its own; the tones are InkWell's. An ink is written as the one part that differs from the text ink at Strongest:

text << ColoredText{ InkGrade::Muted, L"Ping " }                       // the text ink at a step
     << ColoredText{ InkColor::Accent, L"24 ms" }                      // a colour at Strongest
     << ColoredText{ InkWell::redInk(InkGrade::Muted), L" late" };   // anything else, as the Ink it is

A Color stated outright is drawn as it is, and the theme leaves it alone. It is right for art and wrong for an interface.

An ink is also a field of a style, so a style of the application's own carries its ink to every run set in it.

Yellow is drawn, not read. At the 4.5:1 reading threshold on a light page the whole warm arc collapses to brown, so no yellow is both legible and recognisable. Use InkWell::Yellow on an icon and let the text say it in words. A document still reads yellow, so that a text built from code can be written out and read back.

Paragraphs

A line end ends a paragraph: k_endLine, which is L'\n'. Three properties belong to a paragraph rather than to a run of it - its alignment, its indent and its line spacing - and each is a tag written into the text:

WrittenProperty
TextAlign::Left, Center, Right, JustifiedWhere each line stands across the width the paragraph is placed in. Justified stretches every line but the last to that width.
TextIndent{ f }How far the paragraph stands in from the leading edge, its wrapped lines included.
TextLineSpacing{ f }A factor on the height of its lines, 1 being the font's own. The text and a format carry it, and the layouts draw every line at the font's own height whatever it states.

A tag states its field for the paragraph being written and for every paragraph after it, until one written later states it again:

caption << TextAlign::Center << title << k_endLine
        << TextAlign::Left << body;

A tag written in the middle of a paragraph states it for the whole of that paragraph, and the last one written there wins. So one line set apart from the rest takes its tag at its start and gives it back after its line end:

out << TextAlign::Center;
out << InTextIcon{ 220.0f, 24.0f, drawOrnament };
out << k_endLine;
out << TextAlign::Left;

Written before the line end, the TextAlign::Left would take the centring off the very line it was meant for. A field is ended by stating its value again - TextAlign::Left, TextIndent{ 0.0f }.

A text written into another is written as its words and tags would be: its first paragraph joins the one the text has reached, and each of its paragraphs takes what it states over the look in effect where it lands. A paragraph of it that states nothing takes that look whole:

Text list{ TextIndent{ 34.0f }, L"one", k_endLine, L"two" };
page << TextAlign::Center << L"Lists" << k_endLine << list;
// "one" and "two" stand centred and indented by 34.

Edits keep a paragraph's look: a line end typed into one splits it and both halves keep the look, and a paragraph joined to the one above takes that one's - see Copying and Moving Text.

The alignment places lines inside the width the paragraph is placed in. Where that width stands in a control - the whole of its box, or a block the text measures - is the control's text anchor: see Text Anchors. A control can state all three for every paragraph of its text as its TextFormat, and a paragraph's own look stands over the format's - see Text Format.

Spacing and Icons

Spacing

WrittenEffect
Space{ 40.0f }A fixed horizontal gap.
FlexSpace{}, FlexSpace{ minWidth }Takes the room its line has over, pushing what follows to the end of the line. On a full line it is its minWidth.
TabTo{ 150.0f }Moves to an absolute x within the block.
VSpace{ 60.0f }A minimum height for the row it stands in. Shorter than the natural height, it does nothing.

Each stands in the text as one character of its own, k_objectChar, and is a run of its own. A flex space wraps with the word after it, so the words it holds at a line's end stand at the end of the next line when they wrap.

Icons

An icon in text is a DrawIconFunc - anything callable with a DrawIconEvent& - given a box in the flow:

WrittenBox
InTextIcon{ 16.0f, painter }16 × 16, baseline at 85% of the height.
InTextIcon{ 24.0f, 20.0f, painter }Width 24, height 20, baseline at 85% of it.
InTextIcon{ 24.0f, 24.0f, 20.0f, painter }Width, height and baseline stated outright.
InTextIcon{ ..., painter, tag }Any of the above with a Tag the painter can read back.

The painter is handed an event that answers the colours a control's paint event does - inkRgb(ink), textRgb(grade), accentRgb(grade), spotRgb(grade) - with iconRect(), scaleF(...) and canvas(). An icon of width 0 draws outside the flow without occupying it, which is how a bullet is made.

Links and Anchors

A link is a run of text that points somewhere, and an anchor is a run of text a link can point to. Both are fields of a run, so they travel through every edit, copy and paste the rest of the formatting does. What a link does is up to the control holding the text: a TextBox follows it, and a label draws it and nothing more - see Links in a TextBox.

Writing a link

Text text{
    L"See ", LinkText{ L"https://example.com", L"the site" }, L" or ",
    LinkText{ L"#gallery", L"the long gallery" }, L"."
};
See the site or the long gallery.

The target is any string at all - a URL, a path, # and an anchor name, or a word the application answers for itself, such as clafi:ledger. The engine never reads it, and a document and the clipboard carry it whole.

A link is drawn in the accent ink where no colour is written inside it, by itself or through its style. A colour around the link gives way to that ink, and one inside it wins, which is how a link that should not look like one is written:

LinkText{ L"clafi:ledger", ColoredText{ InkGrade::Strongest, L"the ledger" } }

A link inside another is the inner's.

The underline belongs to the control rather than the text: the control underlines the link under the pointer when a click there would follow it, as the second link above shows. It stands clear of the ink it would cross, the way a browser's does - cut where a descender reaches through it, with a gap of its own thickness on either side - see The link underline.

Anchors

text << AnchorText{ L"clue-17", BoldText{ L"Clue 17." } }
     << L" Dmitri stands two doors from whoever was counting.";
// ... and anywhere in the same text:
text << L"The blue landing is settled by " << LinkText{ L"#clue-17", L"Clue 17" };

An anchor is a run rather than a point: it holds text, and a box going to it selects that text. It draws nothing. Where two anchors share a name the first in the text is the one reached.

Text::anchorRange(name) answers the range an anchor holds, or nothing where the text holds no anchor of that name. It walks the runs when it is asked: an anchor is looked for when a link to it is followed, and nothing is kept for it in between.

Links in an edited text

Typing at a link's end goes outside it. A character typed after a bold word is bold, and every other run takes in what is typed at its end the same way. A link keeps to its own words, because a word typed after it is not part of where it points. Typing over the end of a link is different: the text replaced was the link's, and what replaces it is too.

Two links that meet and name one target are one link. They are pointed at, underlined and followed whole, and what is typed where they meet goes inside. An undo that puts a link's last word back produces exactly such a pair, so the link it restores behaves as it did.

An anchor grows at its end the way bold does, since what is typed there is part of what it holds. Deleting the whole of a link or an anchor removes it, and an undo puts it back.

In a Document

How a text is written

A Text in a document is a section of its own styles and its pieces. Import ClaFi.Core.Dom_TextSerializers wherever a blueprint states a Text, and Dt::Value{ L"Caption", Text{} } reads and writes it. A text built over a sheet holding a style named Key, 

Text{ doc,
    TextAlign::Center, StyledText{ TextStyles::Title, L"Title" }, k_endLine,
    TextAlign::Left, L"Press ", StyledText{ L"Key", L"Ctrl+C" }, L" to copy ",
    ColoredText{ InkGrade::Muted, L"the selection" }, L".", k_endLine,
    TextIndent{ 12.0f }, LinkText{ L"#copy", L"More" }, Space{ 4.0f } }

is written, in a document saved without its defaults, as

Caption=[
    Styles=[
        =[
            Ink=muted
            Name=#1
        ]
    ]
    Pieces=[
        P=[
            Align=Center
        ]
        Run=[
            =Title
            Style=Title
        ]
        =""
        |""
        P=[
            Align=Left
        ]
        ="Press "
        Run=[
            =Ctrl+C
            Style=Key
        ]
        =" to copy "
        Run=[
            =the selection
            Style=#1
        ]
        ="."
        |""
        P=[
            Align=Left
            Indent=12
        ]
        Run=[
            =More
            Link=#copy
        ]
        Space=4
    ]
]
  • A piece in no style and linking nowhere is one line: its words unnamed, or an object under its name - Icon, Space, VSpace, FlexSpace or TabTo. A line end in the words continues the value on a line of its own, opened by |.
  • A Run holds anything more: its words as its unnamed value, or an object under its name, and Style, Link and Anchor.
  • A P stands where the paragraph look changes, and states the whole look: Align, Indent and LineSpacing. The paragraphs after it take the same look up to the next P, and a P stating nothing ends the look.
  • The named styles the text carries come first, each after its base - see A text's own styles. An entry states its fields: FontFamily, FontSize, FontWeight, FontStyle, Ink and Scripts. An entry stating no Base is based on the style of its own name up the reading sheet, so Name=Code with Ink=spot is this text's code in the spot ink.
  • A look follows them: an entry for each run style stating more than its base, named # and a number. A look is no style, and reads back as the style of the runs naming it.
  • An ink is an ink colour and a grade: the colour is left out where it is text, and the grade where it is strongest and the colour is not text - spot, accent muted, muted, strongest. A grade between the steps is written as its share, and a colour stated outright as #FF8800.
  • An icon is w,h,baseline. Its painter is a callable and is not written, so it reads back at its extent and draws nothing.

Keys inside an entry are read by name, and a writer puts them in no fixed order.

The document names the styles of the text's sheet and writes them nowhere: Key above is a style of the sheet the text is built over, and reads back where the reading sheet holds it. A sheet is written on its own the same way, as a section of its styles, and ClaFi.Core.Dom_TextSerializers reads and writes a StyleSheet and a TextFormat as well.

JSON and XML write the same pieces in the same order - see Multi-Type Sequences. In XML a run's words are its element's text, and an unnamed piece is text between the elements:

<Pieces><P Align="Center"/><Run Style="Title">Title</Run>
<P Align="Left"/>Press <Run Style="Key">Ctrl+C</Run> to copy ...

Reading it back

A text is read over the reading sheet, or the application's where no scope names one. A StyleSheet::ReadingScope names it while it lives:

{
    const StyleSheet::ReadingScope scope{ &projectStyles };
    caption = (settings / L"Caption").get<Text>();
}

A name the file states is found among the text's own styles first, then in the reading sheet and up its parents; any other reads as words in no style and raises UnknownStyleEvent, as a name written in code does. A Text is read when it is taken out of its node, by get or getTo, so the scope stands around that call and not only around the file's load. Scopes nest, and each is held per thread.

Worked Examples

Flexible space

Text{
    ColoredText{ InkGrade::Muted, L"System" }, FlexSpace{}, BoldText{ L"Online" }, k_endLine,
    ColoredText{ InkGrade::Muted, L"Ping" }, FlexSpace{}, ping, L" ms"
}
SystemOnline
Ping24 ms

Each line's flex space takes whatever that line has left over, so the right-hand column is flush against the right edge and ragged against the left. That is the difference from a tab stop, and the reason both exist.

Tabular alignment

Text{
    BoldText{ L"Component" }, TabTo{ 150.0f }, BoldText{ L"Status" }, TabTo{ 260.0f }, BoldText{ L"Load" }, k_endLine,
    L"Parser", TabTo{ 150.0f }, ColoredText{ InkColor::Green, L"Active" }, TabTo{ 260.0f }, L"High", k_endLine,
    L"Renderer", TabTo{ 150.0f }, ColoredText{ InkGrade::Muted, L"Standby" }, TabTo{ 260.0f }, L"Low"
}
ComponentStatusLoad
ParserActiveHigh
RendererStandbyLow

A tab stop is an absolute x inside the block, so every row lands on the same column whatever the width the block was given. Text that has already passed a stop stays where it is.

A tab character in the text is the other kind of stop: it reaches the next multiple of four spaces of the font the paragraph starts in, so in a monospace font a tab is four columns.

Bullets and inline icons

const DrawIconFunc drawBullet = [](DrawIconEvent& event) {
    FloatPoint center = event.iconRect().center();
    // The icon has no width, so the centre sits on the indent - shift it into the margin.
    center.x -= event.scaleF(16.0f);
    event.canvas().fillCircle(center, event.scaleF(3.0f),
        event.accentRgb(InkGrade::Strongest));
};

Text list{ TextIndent{ 34.0f } };
list << InTextIcon{ 0.0f, 18.0f, drawBullet } << BoldText{ L"Lambda drawables:" } << L" "
     << ColoredText{ InkGrade::Muted, L"any callable renders into the flow." } << k_endLine;
list << InTextIcon{ 0.0f, 18.0f, drawBullet } << BoldText{ L"Reusability:" } << L" "
     << ColoredText{ InkGrade::Muted, L"pass one painter as many times as you need." };
Lambda drawables: any callable renders into the flow.
Reusability: pass one painter as many times as you need.

The indent holds for both lines, since a tag stays in effect until one states it again. The same painter written twice draws twice, so a list of any length costs one lambda.

Do and Don't

Do

  • Name inks, not colours, so a run keeps its meaning through a theme change.
  • State a look the application uses in more than one place as a style in its sheet, and name it.
  • Use TabTo for columns and FlexSpace for two ends of a line. They answer different questions.
  • Give a paragraph tag back after the line end of the line it was written for.
  • Give an icon a Tag when one painter serves several rows and has to tell them apart.

Don't

  • Don't build a text over a sheet that goes before it. A temporary is refused at compile time; a local of the function that returns the text is not.
  • Don't wrap a style in FamilyText or SizedText to change its face. The style's own fields win; state a style based on it instead.
  • Don't keep a wrapper in a variable past the named values it holds.
  • Don't reach for a Color in a control. A literal colour is right for art and wrong for interface.
