# Working Notes

The author's side of the footnotes under `.seedocs/footnotes`, one note per subsystem under the
same name. A footnote says what a thing is and does, for whoever builds on the framework; the
working note of the same name says why it is so, how it is done inside and what happened on the
way - the alternatives weighed, the private members and the order things run in, the defects and
what they showed, the measurements, the things to watch. SeeDocs never reads these.

A heading here is the heading of the footnote it belongs with, so a section is found by the
declaration's name in both files, and a comment's `See <stem>` names the footnote. A subsystem
whose footnotes carry nothing of the author's has no note here.
